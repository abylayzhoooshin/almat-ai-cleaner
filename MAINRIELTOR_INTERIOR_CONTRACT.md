# Контракт фотооценки между Collector, AI Cleaner и mainrieltor

## Ответственность сервисов

- **Collector** публикует полный baseline для AI Cleaner и отдельный список
  объявлений-кандидатов для фотооценки mainrieltor.
- **mainrieltor** оценивает новые объявления и объявления с изменившимися
  фотографиями. Результаты держит во временной таблице до подтверждения AI
  Cleaner.
- **AI Cleaner** хранит оценку в опубликованном clean baseline. Отдельная
  постоянная копия всей таблицы оценок в mainrieltor не нужна.

## Ключ актуальности оценки

Оценка считается актуальной только при совпадении трёх значений:

```text
listing_id + photo_set_hash + evaluator_version
```

- Изменилась только цена или другое поле объявления — фотооценка сохраняется.
- Изменился `photo_set_hash` — прежняя оценка не используется, объявление нужно
  оценить заново.
- Изменилась `evaluator_version` — требуется новая оценка даже при прежних фото.
- Текстовый `content_hash` AI Cleaner и `photo_set_hash` независимы: смена фото
  не должна запускать повторную текстовую очистку.

`photo_set_hash` берётся из Collector и проверяется по его точному алгоритму:

```text
NULL                                             если photo_urls пуст
SHA256("|".join(sorted(photo_urls)).encode())   иначе
```

Порядок фотографий и изменение цены на ключ не влияют. Точные дубли URL
сохраняются и участвуют в хэше. Это публичный ключ обмена; внутренние
`renovation_worker.source_set_key`, `content_set_key` и `evaluation_key` его не
заменяют. Cleaner, первоначальный backfill и mainrieltor обязаны использовать
алгоритм Collector без изменений.

## Поля clean baseline

В строке объявления хранятся:

```text
photo_set_hash
interior_status
interior_score
interior_coverage
interior_evaluator_version
interior_evaluation_key
interior_content_set_key
interior_evaluated_at
```

`interior_evaluator_version` заполняется текущей версией для всех terminal
статусов, включая `no_photos` и `photos_unavailable`. Так mainrieltor может
переиспользовать их по той же тройке и не создавать повторную временную запись.

`interior_score` — число от `1.0` до `10.0` с одной цифрой после запятой либо
`NULL`, когда уровень интерьера определить нельзя.

## Значения результата

| `interior_status` | Значение | Балл |
|---|---|---|
| `ready` | Все нужные фотографии обработаны | Число либо `NULL` при `insufficient` |
| `ready_with_download_gaps` | Часть фото недоступна, оставшихся хватило для ответа | Число либо `NULL` при `insufficient` |
| `no_photos` | В объявлении нет фотографий | `NULL` |
| `photos_unavailable` | Ни одну фотографию невозможно получить | `NULL` |

`interior_coverage` принимает значения:

- `sufficient` — основных помещений достаточно для уверенной оценки;
- `partial` — видна часть квартиры, ориентировочная оценка возможна;
- `insufficient` — жилой интерьер не показан, поэтому
  `interior_score=NULL`.

`pending` и `error` — внутренние временные состояния. Они не означают плохой
ремонт. Объявление остаётся в baseline с неизвестной оценкой и повторяется
согласно политике ретраев.

Ни `NULL`, ни `no_photos`, ни `photos_unavailable`, ни `insufficient` не должны
понижать цену, получать искусственный балл или исключать объявление из baseline.
В расчётах mainrieltor это одна группа: `interior_score IS NULL` — уровень
ремонта неизвестен.

## Работа mainrieltor

1. Получить у Collector список кандидатов на оценку.
2. Сравнить кандидата с последним clean baseline по
   `listing_id + photo_set_hash + evaluator_version`.
3. При полном совпадении использовать готовую оценку.
4. При новом ID или изменившемся `photo_set_hash` выполнить фотооценку.
5. Сохранить результат во временной таблице выдачи для AI Cleaner.

Минимальная временная запись:

```text
evaluation_id
listing_id
photo_set_hash
evaluator_version
status
score
coverage
evaluated_at
acknowledged_at
```

## Работа AI Cleaner раз в 12 часов

1. Целиком получить свежий baseline Collector.
2. Выполнить обычную текстовую очистку только новых и содержательно изменённых
   строк.
3. При пересборке перенести прежние `interior_*` поля, если совпали ID,
   `photo_set_hash` и версия оценщика.
4. Пачкой получить неподтверждённые оценки mainrieltor.
5. Применить только результаты, чей ID и `photo_set_hash` совпадают с текущей
   строкой Collector.
6. Атомарно опубликовать новый clean baseline.
7. После успешной публикации подтвердить mainrieltor применённые результаты.
   Устаревший результат с несовпавшим `photo_set_hash` тоже нужно явно отметить
   как устаревший, чтобы он не выдавался бесконечно.

Полная пересборка автоматически удаляет объявления, которых больше нет в
baseline Collector. Их оценки отдельно удалять не требуется.

## Очистка временных результатов mainrieltor

Удалять результат только после подтверждения AI Cleaner:

```text
acknowledged_at IS NOT NULL
AND acknowledged_at < now - 24 hours
```

Удаление просто по возрасту записи запрещено: при остановке AI Cleaner более
чем на сутки неподтверждённая оценка была бы потеряна.

## Порядок запуска после обслуживания

1. Collector собирает свежие данные.
2. AI Cleaner работает в `CLEANER_API_ONLY=1` и отдаёт последний baseline без
   запуска нового цикла.
3. Запускается mainrieltor и обрабатывает накопившийся список Collector. Окно
   догоняющей загрузки должно покрывать весь фактический простой; фиксированных
   12 часов недостаточно при более долгой остановке.
4. После обработки очереди AI Cleaner переключается на
   `CLEANER_API_ONLY=0`.
5. Первый цикл Cleaner получает свежий baseline и готовые оценки, затем
   публикует согласованный снимок.

Надёжный постоянный вариант догоняющей загрузки — курсор последнего события
Collector с небольшим перекрытием и дедупликацией по
`listing_id + photo_set_hash`.

## Первоначальный массовый проход

Текущий `interior.sqlite3` нужен только для первоначальной разметки и
возобновления после сбоев. Его результаты добавляются прямо в clean baseline.
Переносить всю эту SQLite в постоянную БД mainrieltor не требуется. После
второго прохода по свежему baseline, проверки публикации и резервной копии
временный backfill можно удалить.
