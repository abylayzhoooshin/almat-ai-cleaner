# Оценка интерьера

Рабочая реализация разделена на независимые слои и пока не импортируется
оркестратором:

- `renovation_scorer.py` — prompt, схема, запрос и валидация;
- `renovation_store.py` — SQLite-кэш, связи объявлений и журнал попыток;
- `renovation_worker.py` — скачивание, SHA-256, проверка кэша и вызов модели;
- `run_renovation_standalone.py` — отдельный реальный прогон без Stage 2/3.

## Зафиксированная конфигурация

- версия: `simple-decimal-v4-original-gpt6-luna`;
- модель: `gpt-6-luna`;
- Responses API, Structured Outputs;
- `temperature=0`, `reasoning.effort=none`, `detail=low`;
- максимум 1 400 выходных токенов;
- один прямой запрос по всем фотографиям объявления;
- итоговая шкала 1,0–10,0 с одной цифрой после запятой;
- при недостаточном покрытии: `score=null`, пустой `evidence` и объяснение
  в `limitations`.

Выбранный prompt и JSON Schema являются частью модуля. Изменение модели,
prompt, схемы или правил валидации требует новой `EVALUATOR_VERSION`; старую
версию нельзя молча переписывать.

## Граница ответственности

`renovation_scorer.py` принимает подготовленные изображения с уникальными
`photo_id`, создаёт запрос, вызывает переданный совместимый Responses client и
валидирует результат. В нём намеренно нет:

- чтения карточек collector;
- скачивания и постоянного хранения фотографий;
- очереди и повторов;
- влияния на ценовой скоринг;
- форматирования Telegram.

Worker скачивает изображения только для проверки содержимого и запроса, не
сохраняя байты постоянно. В API отправляются оригинальные байты с `detail=low`;
после запроса они освобождаются. Общий набор ограничен 15 MiB и загружается
пачками по два, чтобы лимит действительно ограничивал RAM. Store сохраняет
результат, usage, попытку и актуальную
связь `listing_id → evaluation_key`.
`RenovationStore.iter_baseline_exports()` выдаёт согласованный компактный набор
`interior_*` полей для присоединения к baseline и не требует разбирать JSON.
Для frozen baseline используются уже сохранённые `photo_urls`: существование
страницы объявления не проверяется. Если все URL окончательно отвечают 404/410,
фиксируется `photos_unavailable` без API-вызова; временные сетевые сбои остаются
в `error` для повторной попытки.

## Кэш

Финальный ключ результата рассчитывается как:

```text
content_set_key = SHA256(отсортированного уникального набора SHA-256 фото)
evaluation_key  = SHA256(content_set_key + evaluator_version)
```

`listing_id` хранится как связь с результатом, но не является ключом оценки.
Поэтому снижение цены при прежних фотографиях не вызывает новый запрос, а смена
фотографий под тем же ID вызывает. Цена, описание и причина события в ключ не
входят.

## Проверка

```powershell
python -m unittest -v test_renovation_scorer.py test_renovation_worker.py
```

Тесты не обращаются к API. Они проверяют зафиксированные параметры запроса,
десятичную шкалу, `insufficient`, ссылки evidence на существующие фото,
уникальность `photo_id`, независимость ключа от порядка/дублей и сценарий
`new → price_drop` с одним вызовом модели, частичные сбои скачивания, ограничения
входа и экспорт результата в baseline.

Standalone-runner читает ключ скрытым вводом и не сохраняет его:

```powershell
python run_renovation_standalone.py
```

SQLite по умолчанию находится в `DATA_DIR/interior/renovation.sqlite3`.
